# WorkFlowHub 需求与验收

2026-10-10。个人求职实践项目；代码辅助生成不等于候选人已经独立掌握。目标：中小企业 IT 工单从申请、指派、处理到关闭可追溯，关联设备资产。两个独立目录 workflowhub 与 workflowhub-qa，均位于 D 盘；QA 通过 HTTP 测试业务项目，不复制业务代码。

## 角色与资源权限
|角色|权限|
|---|---|
|Administrator|创建账号、查询全部工单、编辑及指派、维护资产、查看业务历史|
|Engineer|查询本人创建或分配给自己的工单；处理分配给自己的工单；只读资产|
|Requester|创建、查看本人申请的工单；在 OPEN 状态编辑；确认关闭或重新打开自己的工单；只读资产|

不提供自助注册、删除工单、删除用户，减少权限与历史保留歧义。全部账号由管理员创建。登录失败用统一响应；密码 scrypt + 随机盐。使用随机不透明 Bearer 令牌，仅存 SHA256 摘要，8 小时到期，退出删除会话。浏览器只在内存保存令牌；刷新需登录。演示密码由本地初始化脚本随机生成，真实凭据不进 Git。

## 验收编号
- AUTH-01：管理员创建三类账号，登录、本人信息、退出及令牌到期有效；账号重名返回 409。
- ACL-01：资源读取、修改、记录和历史查询均实施角色与所有权检查；未知资源 404，越权 403。
- TKT-01：工单含唯一编号、标题（1—120）、描述（1—4000）、优先级（1—3）、创建者、负责人、时间、状态、版本；可关联存在且非报废资产。
- TKT-02：分页 page≥1，size 1—100；状态、负责人、关键词组合；created_at 和 id 双键稳定排序；状态及负责人统计遵守同一资源权限。
- FLOW-01：管理员指派工程师：OPEN→IN_PROGRESS；已 IN_PROGRESS 可重新指派。分配对象必须是 Engineer。
- FLOW-02：管理员或被指派工程师可 IN_PROGRESS→RESOLVED；管理员或创建者可 RESOLVED→CLOSED；管理员或创建者可 RESOLVED/CLOSED→OPEN，并清空负责人。其他迁移返回 409。
- EDIT-01：工单创建者只能在 OPEN 编辑标题描述；管理员可编辑非 CLOSED 工单。每个修改请求必须带 version；冲突 409，不覆盖新版本。
- NOTE-01：授权用户可添加处理记录（1—2000）；已关闭工单不能追加记录。
- AST-01：管理员登记唯一资产编号，名称（1—120），状态 active/maintenance/retired；其他角色只读。
- AUDIT-01：工单创建、编辑、指派、状态改变、处理记录、账号及资产变更留下 actor、UTC 时间、动作、变更字段；业务与审计同事务，任一失败全部回滚。
- SEC-01：ORM 绑定参数；不得记录密码/令牌；非法输入 422；未登录 401；资源冲突 409；数据库不可用返回通用 503。
- UI-01：浏览器可完成账号登录、创建工单、筛选、查看历史、指派、处理、关闭、重开、资产登记与状态维护；角色操作可见性服从权限。
- OPS-01：Alembic 迁移；Compose 启动 MySQL 8.4 和应用；pytest/HTTP 黑盒套件、Postman 集合、真实列表性能实验、CI 配置及复现文档。

## 范围
单体 FastAPI + SQLAlchemy 2 + MySQL；SQLite 仅作为便携演示与快速测试后端。无 Redis 缓存与限流需求，不引入。浏览器采用原生 HTML/CSS/JS 同源页面，无需前端构建。云部署、多租户、文件上传、通知邮件不在本次范围。
