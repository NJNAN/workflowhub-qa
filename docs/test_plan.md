# WorkFlowHub测试计划
验收对象为个人自研业务系统，AI辅助实现；业务白盒与独立黑盒分层记录。需求基线PRD.md，完成报告日期2026-10-10。

范围：AUTH/ACL/TKT/FLOW/EDIT/NOTE/AST/AUDIT/SEC/UI/OPS。目标是在三角色正常流程外，确认拒绝越权、非法参数、非法状态、陈旧版本与失败提交。未包含公网安全渗透、跨浏览器自动化、移动真机、长期容量和生产SLA。

环境：Windows11，Python3.12.14；ASGI+SQLAlchemy临时SQLite，MySQL8.4.11容器专用workflowhub_test；QA启动真实uvicorn进程进行TCP请求，另对Compose进行同合同回归。测试库与演示库分开。随机密码仅存在本地忽略文件，CI用可丢弃凭据。每案例重建业务数据库，QA共享服务但用唯一资产编号/幂等键；other账号保持无工单。

方法：非法/合法等价类；标题0/1/120/121等边界；4状态两两迁移矩阵；身份与资源两维权限；两线程同版本竞争；人为令审计失败的事务实验；真实FK和迁移往返；输入注入字符串与LIKE通配符。独立HTTP不导入业务内部实现。UI是人工浏览器验收，不混入自动化计数。

入场：环境可创建临时数据库，健康端点与迁移可执行。退出：关键功能/权限/事务案例全部通过，已发现P2完成对应验证；没有未处理P1。缺陷按P1破坏授权/数据、P2功能安全问题、P3体验区分，不为了数量编造缺陷。故障注入不是实际开发Bug。

执行：业务README的pytest+coverage，scripts/verify_mysql.py，独立仓pytest；保存JUnit、SQL/HTTP原始样本、失败回归日志。默认Windows沙箱曾使ASGI/进程启动停滞，获执行环境授权后恢复；该现象不计产品缺陷。远程Actions和Postman客户端没有执行，不能标为通过。
